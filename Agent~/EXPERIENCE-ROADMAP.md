## 产品定位

当前 `xy-unity-agent` 是工作流技能：复用 Codex 的推理与 XY MCP 的操作能力。它已经能提供检查顺序和项目经验；进一步的价值应落到可运行的检查器、可读取的运行证据和可重复的验证，而不是继续增加用户需要填写的面板。

下面是建议开发项，不代表本轮已实现。新增命令名仅作设计示例。

## 优先级 1：点位体检器

**触发需求**：迁移点位、复制多个模块、视频或手势没有进入流程、资源缺失，以及代码正确但 Prefab/注册没跟上。

建议提供只读的 `unity_audit_module`，智能体在处理相关任务时按需调用：

- 基础层：主 Prefab 是否可加载、Missing Script、指定序列化引用缺失、模块内及相关依赖的 GUID 冲突。
- 模块适配层：ModuleConfigAsset、namespace、入口类型、asmdef、主 Prefab 和注册表的映射。不假定所有工程都用同一份 data.json 或同名目录。
- 入口核对：列出找到的同步/异步入口与实际测试加载器调用关系；无法确定动态调用时返回需运行验证，不能只凭方法存在下结论。
- 平台核对：模块关键初始化与清理的条件编译线索；不能把在 Android 上能编译等同于初始化顺序正确。

统一输出 `ruleId / severity / target / evidence / expected / actual / supported`，支持面板定位对象，也能被 MCP 读取。基线只读，不默认修改 Prefab 或生成新 GUID。

现有基础：`inspect_project.py` 能盘点配置字段、asmdef、模块内重复 GUID 和相对路径模板差异。缺口：没有 Unity 对象级检查、模块标识语义对照、加载器适配和统一问题模型。

来源：`01a15d59-2a71-7c43-beeb-1a5edc59e627`、`01a142ce-ebdc-7d63-b7b6-da3bae9c77d6`、`019f17a4-75fa-77f3-b312-c54cb41bc2ef`。

**最小验收**：用隔离的测试 Prefab/模块分别制造 Missing Script、引用缺失和配置入口不存在；报告定位正确；合法的业务模板分叉不作为错误；执行前后资产内容不变。

## 优先级 2：点位运行记录与重入回归

**触发需求**：第一次正常、第二次不触发；退出后旧回调继续执行；重复播放保护改完又无法启动；手势恢复后模型仍不出现。

当前 RequestLog 记录的是 MCP 请求类型、耗时和传输结果，不是点位业务执行过程。建议增加可选的业务观测层：

- 每次进入分配 sessionId，记录模块、步骤、触发源、开始/完成/取消/失败以及对象状态。
- 明确记录进入、退出、媒体准备/播放、按钮开放、追踪变化、结束 UI 和关闭点位。
- 记录旧 session 在退出后仍尝试执行的动作，帮助定位迟到回调。
- 在有适配器的点位中运行“进入→中途退出→再次进入”的回归，检查事件次数和目标状态；未知模块返回不支持，而非假定可以自动驱动。

SDK 无关的事件模型可放在通用层，Rokid/ARMaz 的接入放在独立适配器。采集默认限量，不记录每帧 Pose 或全部音频数据，不强制给所有业务代码注入探针。

来源：`019f01bf-f7b3-7970-bbf7-518a2becd398`、`01a15d59-2a71-7c43-beeb-1a5edc59e627`、`01a0ad1d-32dc-7b72-8de4-05c44c4aa15e`。

**最小验收**：对测试模块复现“退出后迟到回调”和“第二次进入标志未复位”；能按 session 区分两次进入，并给出最后正常步骤与首个异常；Editor 模拟不能冒充设备验证。

## 优先级 3：带语义预检的批量编辑与验收

历史中有明确请求：统一修改 48 个文字对象的缩放、多个点位复用手掌功能、复制点击音效、迁移 4 个模块。也有“全部改”实际只指业务流程而非资产编辑的表述，不能单凭关键词执行批量写入。

已有 `unity_batch` 解决了参数预检、顺序执行、首错停止和结果断言。下一步补：

- 写入前解析唯一对象、区分场景实例与 Prefab 资产，检查属性存在和类型，返回旧值与新值的修改计划。
- 使用稳定对象定位，避免同名节点误操作；目标状态已变化时要求重新生成计划。
- 每个修改关联读回验证，输出修改成功、验证成功、未执行和执行状态未知，而不是统一显示“完成”。
- 有条件时复用现有 Pipeline transactional batch；不支持 Undo 的操作明确排除或独立处理，不能给所有修改承诺回滚。

来源：`019f123e-b893-7d60-b7ef-ee02c5d7f96a`、`01a0571e-cf35-7541-bb5a-85639e06aaf1`、`01a0a2ee-e28e-72b0-a4a8-68f41b7abe14`、`01a15d59-2a71-7c43-beeb-1a5edc59e627`。

**最小验收**：第二个目标属性不存在时整批写入尚未发生；同名对象可检测歧义；写入后读回与预期一致；中途失败报告保留已执行范围，不伪称已回滚。

## 优先级 4：实际加载版本核对

**触发需求**：本地修复/转码完成，设备体验却没变。历史案例涉及本地 DLL 与实际测试入口、SLAM/Cloud 视图绑定不同视频、资源包与缓存不一致。

建议形成统一的只读核对报告：模块 Ident、入口程序集、资源引用、文件哈希、构建时间/版本，以及目标设备上实际加载的路径或配置。

先提供本地报告；只有用户指定设备且具备 ADB/配置访问能力时比较设备端。不自动清缓存、重装、上传或发布；无法读取运行端时标注未知，不推断已经更新。

来源：`01a15d59-2a71-7c43-beeb-1a5edc59e627`、`01a0ebf8-ff43-77a2-a448-21b5893405be`。

**最小验收**：测试资源的本地和模拟部署清单哈希不同时，能定位差异；缺少设备清单不能返回一致；报告不泄露私有服务器凭据。

## 后续候选：可配置交互能力库

重复需求包括 NPC 移动/朝向、语音完成后解锁交互、空闲提示、点击音效、结束 UI 后关闭，以及手势丢失后的显示策略。

适合提炼小型能力组件和适配器，而不是继续复制整套点位 Template。尤其“追踪丢失立即隐藏、保持最后位置、允许短暂抖动”是不同产品策略，不能把某次历史修复写死成全局行为。参数应有归属与生命周期，迁移时显示依赖，不默认覆盖用户模块。

历史生成器已经有过模板目录勾选功能；下一步有价值的是依赖检查、预览和回归验证，不应把已有勾选界面重新开发一遍。历史功能是否仍存在需检查对应工程。

来源：`019fa7fd-1fb7-7c31-ae4a-56a956cc5657`、`01a0ad1d-32dc-7b72-8de4-05c44c4aa15e`、`019fabec-3b21-73f0-8888-580612c22f6a`。

## 推荐推进方式

先在一个真实、可复现问题的点位上做只读体检器，验证报告能否减少人工查找；然后接入同一模块的 session 运行记录和重入回归。带着这些可观测结果完善批量编辑的语义预检与验收。

用户仍直接用自然语言描述需求。插件检查器和记录器把事实交给智能体，不增加日常复制、选择和填写步骤。每项能力都记录可支持的工程结构、验证层级和限制。

本轮只进行了资料挖掘与路线归纳，没有实现以上新检查器、记录器或设备接入，也没有训练模型。Timeline 专项继续暂缓。
