# 生命周期、异步和媒体流程

## 定位“第一次正常，第二次异常”

把一次进入视为一个会话，明确初始化、进入、播放、交互、完成、退出、再次进入的状态与异步所有权。检查：

- 标志位是否在再次进入复位；结束、下一关、正确反馈是否走不同分支。历史反馈 UI 缺失曾与最终关卡绕过反馈分支有关，不能只加重复触发开关。
- 订阅与解绑是否成对、是否重复绑定；取消令牌是否绑定该次进入，退出后旧 continuation 是否仍能改 UI。
- 令牌取消与 Dispose 的时机；并发音频、手势等待不能无意共享一个会被互相取消的任务。
- GameObject 禁用或追踪丢失后是否取消延迟、关闭交互、复位动画和销毁临时对象；再次激活能否重新使用。

重复进入保护不是一律忽略所有 `OnEnter`：先确定测试入口与正式入口的约定。自动播放与手动启动只能有清楚的所有权；不要同时启动。必须保证初始化失败或取消后能恢复重试。

## 音视频与 UI 时序

- 检查实际的 MediaComponent/Audio/Role 接口、资源加载完成、播放开始、自然结束、手动停止与失败事件。`GetMoivePath` 等历史拼写只是搜索线索，不能猜 API。
- 用户说 `01–05` 时保留编号宽度，核对实际资源文件、字幕、配置映射；不擅自改成 `1–5`。
- “语音播完才能注视”“提示在语音最后两秒出现”“结束 UI 展示后关闭”要区分事件依赖和用户指定展示时长。用户要求的展示延迟可以保留；关键流程不能只依赖猜测的固定秒数。
- 等待媒体准备、加载、播放结束时定义失败/退出路径。资源不存在或播放失败不能无限阻塞点位，也不能伪报完成。
- `PoiEnd` 的声明不代表有调用。找到业务结束调用点、对外关闭消息和实际关闭动作，确认结束提示展示在关闭之前，关闭只由一个流程负责。
- 如果已有 Director 影响流程，核对自然结束、手动 Stop、退出解绑和结束幂等。不要把窄帧时间窗口当作可靠完成事件，也不要将所有 stopped 无条件认定为自然完成。

验证最少覆盖：首次播放、完成后再次进入、准备/播放中退出、快速切换交互和缺失资源。无法运行时给出具体验证步骤，而不是宣称已复测。
