# 技术方案整理

在用户要求方案、讨论或先看时输出可实施的设计；用户已经要求实现时，按现有授权推进，不把每个文件写入重复变成审批步骤。

从实际源码、Prefab 和 SDK 确认交互方式、生命周期、平台和异步封装。能从工程取得的信息先读取；只询问无法推断、会改变结果的需求。不要用“75% 信心”替代可检查的完成条件。

按任务复杂度说明：目标和影响模块；正常流程和关键状态；初始化/退出清理；媒体或资源失败路径；左右手与追踪恢复；Editor 与设备差异；验证方法。已有流程可以用简短状态表表示，不必总输出同一个长模板。

特别区分展示时长与业务触发条件，例如“答对后等待三秒”不能变成“任意选择后等待三秒”；“语音播放完开放按钮”不能变成按猜测时长开放。

只做方案时交付到方案即可；不要自动编码。实现任务的普通可逆步骤无需逐文件要求确认；涉及外部发布、删除用户数据或改变原需求范围时再处理新增授权。
