# 诊断、资源与实际运行版本

## 证据层级

记录当前工程、入口、场景/Prefab、模块、平台、复现步骤和首个错误。优先当前日志与对象状态，其次源码调用链；历史助手的“根因”只作为候选。导出中包含恢复副本、未归属会话和网页/网络话题，不能按标题自动当作 Unity 知识。

## 看起来更新了，设备却没变

按链路核对：源码/本地资源 → 模块 DLL 或资源包 → 发布配置/视图映射 → 下载缓存 → 实际加载路径/哈希 → 日志。历史视频案例中，本地转码正确但 SLAM/6DoF 配置仍指向旧 4K 资源；这提示先核对实际绑定，不代表所有卡顿都是该原因。

- 检查模块 namespace、资源包标识、大小写、文件编号与加载器约定；`AssetDatabase` 找到文件不代表设备包内存在。
- 发布与设备路径可能有不同视图配置。只查看任务相关配置并遮盖凭据，不把完整私有配置写进通用技能。
- 不用删除整个缓存、重装应用或覆盖模块来替代定位。确需这些动作时明确目标和数据影响，遵守当前用户授权。

## 设备、媒体和性能

只有目标 ADB 设备已确认时才取该设备日志，核对 serial、包名、进程与时间窗口。保留首个异常及相邻上下文；不要把另一进程报错归因于 Unity。

视频体积小不代表解码轻。按实际媒体检查编码、分辨率、帧率/GOP、音频、播放链路和设备解码日志，结合当前设备能力判断；不把历史 H.264/30fps 参数当万能标准。先确认实际播放的就是待测文件。

内存、DrawCall、GC、CPU/GPU 问题用当前 Profiler/Frame Debugger 或日志数据支撑。区分 Editor 与真机结果。普通枚举转整数不等于装箱，不能凭印象制造性能结论。

资源工具返回路径后可以查看预览；pending 只表示未完成。读取 Prefab 层级、序列化引用与 GUID 时要考虑嵌套 Prefab 和运行时实例，不把文本搜索没有命中解释为对象绝对不存在。
