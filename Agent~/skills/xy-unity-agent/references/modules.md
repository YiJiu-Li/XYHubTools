# 点位与模板

历史工程常见 `Assets/Modules/<Ident>/Main/Scripts`、`Main/Res/Pfbs`、模块根部 `ModuleConfigAsset.asset` 和项目级 `Assets/Modules/data.json`。这些是定位线索，不是要求每个 Unity 项目照此建目录。

## 创建或迁移

1. 找一个当前项目中能正常加载、相似交互的模块，对照入口、PoiMgr、本地 Template、主 Prefab 和注册配置。先检查模块创建工具是否已有能力，不另造不兼容生成器。
2. 核对目录、Ident、namespace、asmdef、入口类、主 Prefab、资源包名、PoiCode 与注册表的映射。模块目录名不一定等于入口类；不要把 `FY5076`、`XYFY5076` 和旧点位码简单全局替换。
3. 检查实际加载器调用 `OnEnter/OnExit` 还是异步入口。历史中出现过“正式入口调用异步方法，Editor 测试入口只调用同步方法”的差异；从当前调用链确认，不能只看重写方法存在。
4. 确认资源实际来自 AssetDatabase、本地 DLL、AssetBundle 还是设备缓存。源码编译成功不意味着运行端 DLL 已替换。没有授权时不上传、发布或提交。
5. Framework 和模块本地 Template 同名文件可能有业务分叉。按相对路径和内容比较后逐处迁移；`Util.Node.FindNode` 与 `Util.FindNode`、Task/UniTask 封装等必须匹配本模块版本。

## Rokid 点位交付结构

- 点位资源形成独立闭包。依赖可以来自本点位目录以及项目明确批准的 Framework、SDK、包或公共资源目录，但不能指向另一个点位目录。需要复用其他点位的业务资源时，将资源及必要依赖复制或迁移到本点位并生成正确 GUID；真正跨点位共用的内容应由用户确认后提升为公共资源，而不是继续挂在某个点位名下。
- 交付 Prefab 预建稳定层级：UI Canvas/面板、视频显示与播放器承载节点、AudioSource、模型/特效容器、相机前方锚点、射线/碰撞节点和加载占位等应尽量在 Prefab 中存在，可默认禁用并在进入时复用。这样美术和策划能直接调整位置、尺寸、材质与层级。
- 点位业务 MonoBehaviour 不直接挂在交付 Prefab 上。沿用当前模块入口、PoiMgr 或加载器的既有方式，在运行时 `AddComponent` 或通过工厂挂载，并立即注入/查找预建节点后初始化。再次进入前检查组件是否已存在，避免重复挂载、重复订阅和重复播放。
- 动态创建只用于数量运行时决定、短生命周期、池化实例或 SDK 明确要求的对象。若必须动态创建 UI、视频或交互节点，说明为什么不能预建，并保证父级、坐标、材质、事件相机、释放和再次进入行为可验证。
- 因业务脚本不在 Prefab 上，不能依赖 Inspector 直接序列化其字段。优先由初始化器显式注入预建节点；沿用项目已有节点查找工具时使用稳定路径并在初始化时一次查找、缓存和校验，不在每帧重复 `Find`。

## 序列化引用

- 移动现有资源要保留 `.meta`；同工程创建新副本要生成新 GUID 并正确重映射内部引用。不要原样复制全部 `.meta` 或批量删掉元文件后希望引用自动修复。
- 源码字段或层级调整后检查 Prefab 中绑定对象；原始 YAML 同名字符串不是引用有效性的充分证据。
- 对点位 Prefab 和其依赖做反向检查：任何落到其他点位目录的 GUID、AssetBundle/Addressables 地址或配置路径都视为跨点位依赖，除非它属于明确批准的公共资源。
- `Root/PB-zh/...`、`NLQ`、`Button_Ray` 等历史名称不能当作全项目固定结构。节点找不到时读取实际 Prefab 层级，确定初始化时机和父子级。
- 不自动把用户当前按钮体系替换成相似 SDK 组件。点位业务脚本遵守本项目的运行时挂载约束；SDK、按钮等辅助组件的创建方式和日志方式仍以当前工程与模板为准。

完成时给出受影响的模块标识、运行时脚本挂载入口、Prefab 预建节点、资源依赖、配置清单，以及是否需要重新生成模块 DLL 或资源包。只声明已实际执行的构建。
