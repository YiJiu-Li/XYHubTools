# 手势、凝视和空间交互

按最早失败位置检查：SDK/初始化 → 追踪与手别 → 手数据 → 手势状态 → 交互代理 → 物理或 UI 事件 → 业务回调。先观测链路，不一次替换整套组件。

- 从当前包和已用模板读取 GesEventInput、GestureBean、UBtn、UPalm 等 API，不硬编码 SDK 版本或权限名。
- 订阅归属与生命周期匹配：会话级订阅在进入/退出或启用/禁用时成对处理；对象级订阅才适合 Awake/OnDestroy。只在 OnDestroy 解绑不一定能覆盖点位反复进入退出。
- 检查当前模块实际使用的 UniTask、DTask/YieldAction 和独立取消令牌约定，避免全局任务互相取消。沿用工程异步风格，不把“禁止 Coroutine”作为跨项目硬规则。
- 区分 Android 真机订阅和 Editor 模拟路径；`#if UNITY_ANDROID` 不是模拟实现，也不能仅靠包住组件内部而漏掉外层初始化/清理。
- 状态变化事件只在状态翻转时触发。注册时若手已经在追踪，应读取当前状态做初始化；不要期待一定会再次收到追踪成功边沿事件。
- 位置/旋转跟随可以在有效追踪期间持续更新；一次性点击、计分、播音频不能放在每帧 Pose 回调里。
- 左右手明确枚举匹配；`!= LeftHand` 可能包含 None 等状态，不等于右手。确认左手代理也建立并绑定。
- UBtn 无响应时检查代理坐标空间、激活状态、Collider/Trigger/Rigidbody/Layer、回调注册和取消。克隆带组件的手代理后再次 AddComponent 可能导致重复回调。
- 空引用检查具体缺失层级、对象构建与 Initialized 调用顺序；不要改用另一套按钮类型绕过尚未定位的问题。
- 手数据丢失是正常状态，应隐藏代理并取消待确认动作。Vector3/Quaternion 是值类型，不能用 null 判断有效追踪。
- SubPoi、Area、Gaze 的启用时机应跟随当前流程状态，检查是否与主点位重复处理同一次进入/退出。
- World Space UI 关注 Canvas/EventCamera、遮挡、射线与碰撞体、用户视野、局部/世界坐标；Editor 可点不等于设备手势可用。

重复进入、追踪丢失再恢复、注册前已追踪、左右手切换、快速切换按钮，是最有价值的回归场景。
