# 手势、凝视和空间交互

按最早失败位置检查：SDK/初始化 → 追踪与手别 → 手数据 → 手势状态 → 交互代理 → 物理或 UI 事件 → 业务回调。先观测链路，不一次替换整套组件。

- 从当前包和已用模板读取 GesEventInput、GestureBean、UBtn、UPalm 等 API，不硬编码 SDK 版本或权限名。
- 订阅归属与生命周期匹配：会话级订阅在进入/退出或启用/禁用时成对处理；对象级订阅才适合 Awake/OnDestroy。只在 OnDestroy 解绑不一定能覆盖点位反复进入退出。
- 检查当前模块实际使用的 UniTask、DTask/YieldAction 和独立取消令牌约定，避免全局任务互相取消。沿用工程异步风格，不把“禁止 Coroutine”作为跨项目硬规则。
- 区分 Android 真机订阅和 Editor 模拟路径。直接访问 `GesEventInput`、`GestureBean`、`HandType`、骨骼或手势枚举的真机运行时代码必须受 Android 条件编译保护；通常使用 `#if UNITY_ANDROID && !UNITY_EDITOR`，Editor 模拟单独使用 `#if UNITY_EDITOR`。订阅、解绑、初始化和清理必须使用相同宏条件，不能只包住其中一半。
- 非 Editor、非 Android 的 Player 路径必须安全降级为无手势数据，不能让 `#else` 默认执行 Rokid SDK。纯 SDK 适配器可以整体放进 Android 宏；若其他平台代码会引用该组件，则保留平台无关的公开接口，把 SDK 类型与调用隔离到宏内或 Android 专用适配层。
- 状态变化事件只在状态翻转时触发。注册时若手已经在追踪，应读取当前状态做初始化；不要期待一定会再次收到追踪成功边沿事件。
- 位置/旋转跟随可以在有效追踪期间持续更新；一次性点击、计分、播音频不能放在每帧 Pose 回调里。
- 左右手明确枚举匹配；`!= LeftHand` 可能包含 None 等状态，不等于右手。确认左手代理也建立并绑定。
- UBtn 无响应时检查代理坐标空间、激活状态、Collider/Trigger/Rigidbody/Layer、回调注册和取消。克隆带组件的手代理后再次 AddComponent 可能导致重复回调。
- 空引用检查具体缺失层级、对象构建与 Initialized 调用顺序；不要改用另一套按钮类型绕过尚未定位的问题。
- 手数据丢失是正常状态，应隐藏代理并取消待确认动作。Vector3/Quaternion 是值类型，不能用 null 判断有效追踪。
- SubPoi、Area、Gaze 的启用时机应跟随当前流程状态，检查是否与主点位重复处理同一次进入/退出。
- World Space UI 关注 Canvas/EventCamera、遮挡、射线与碰撞体、用户视野、局部/世界坐标；Editor 可点不等于设备手势可用。

## AR 展示与通用模板

- 内容需要出现在用户前方时，先复用当前项目已有的相机前方定位/锚点脚本或模板，区分“进入时摆放一次”和“持续跟随相机”两种语义。距离、高度、局部偏移和父级坐标来自当前点位配置，不把某个历史数值写成全项目常量。
- 只需水平朝向用户时保持世界 Up 不变，只根据相机与对象在 XZ 平面的方向计算朝向；相机和对象水平位置重合时保留上一次有效旋转，避免零向量和俯仰/翻滚抖动。先查项目已有的 Billboard、Face/LookAt Camera 或同等行为脚本，不因类名不同重复实现。
- 相机前方节点、World Space Canvas、视频面、提示 UI 和交互碰撞体优先在点位 Prefab 中预建；运行时脚本只负责定位、显隐、赋值和重置。持续更新确有必要时集中在一个共享组件中，不让多个业务脚本同时抢写 Transform。
- 手势功能先复用 Framework、Template 或正常点位中的手势模板和手代理创建流程，核对 GesEventInput、GestureBean、UBtn、UPalm 等实际 API 与清理方式。业务脚本仍由入口动态挂载，模板负责提供可复用的节点与初始化约定。
- 如果当前项目找不到通用脚本或手势模板，先报告缺口和已检索范围，再决定新增到公共层还是仅做本点位实现；不要默认从另一个点位目录建立依赖。

重复进入、追踪丢失再恢复、注册前已追踪、左右手切换、快速切换按钮，是最有价值的回归场景。
