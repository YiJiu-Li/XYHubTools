# XY Desktop Agent Developer

先读当前项目规则、架构、Cargo/前端包清单、锁文件、Tauri 配置和已实现的运行协议。存在 `.codegraph/` 时先用 CodeGraph 定位代码。Rust/Tauri/Vue 是这个专项的适用范围，不是迁移其他技术栈的授权。

读取 [运行架构与验证](references/runtime-architecture.md)，定位任务属于 Agent 调度、模型适配、工具执行、IPC、UI 状态、存储还是打包，只修改相关层。

## 保留的设计原则

- 区分 Session 与 Run：Session 是对话容器，Run 是一次执行。流事件用 sessionId/runId/toolCallId 关联，终态明确，迟到事件不能污染新的执行。
- Agent 定义、工具 schema 与实际可执行能力分离；工具必须在后端注册、校验和授权，不能只相信模型输出或前端隐藏按钮。
- 长期知识区分设计、用户偏好、技能和参考资料；使用按需检索，保留来源和版本，不把历史对话自动提升为指令或永久规则。
- 流式 UI 对增量做合并和有界缓存，工具参数片段聚合完成且验证后再执行；取消传播到请求、子任务和等待状态。
- 环境中的有效模型与上下文限制来自配置、提供方能力或官方说明，不按模型名字符串猜测，也不从旧文件固定到某个 Claude/GPT 版本。
- 处理密钥时沿用当前安全存储，不放入示例配置、会话日志或原始请求调试记录。原始记录应可关闭、脱敏并有保留策略。

用户明确要求实现时完成实现与验证；只要方案时交付方案。日常已授权的可逆修改不逐文件请求确认。工具确认机制处理真实权限边界，不能把任何工具调用都变成弹窗；已有批准范围内的操作不反复询问。

沿用当前 Rust 异步运行时和错误类型，区分 CPU/IO 密集工作与阻塞库；不要无条件 tokio::spawn 或把阻塞 SQLite 查询直接放进异步热路径。Vue 现用 Composition API/状态管理约定优先于通用目录模板。

根据改动检查工具循环、事件顺序、并发 Run、取消/错误终态、存储恢复及打包资源。只运行当前仓库真实存在的命令，不照搬 Locus 的私有路径、构建脚本或环境变量。

本专项不自动启动多智能体、换模型、发送消息、上传知识或新建独立应用。当前 Unity 插件继续复用 Codex + XY MCP；这里只有未来桌面应用开发时按需使用的工程方法。
